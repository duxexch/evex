Multiplayer Games Configuration
Real-Time Sync, Safety & Governance – Technical Roadmap
Objective

Transform the multiplayer games system into a fully synchronized, real-time, financially safe, and administratively governed platform, where the database is the single source of truth and all clients stay consistent without manual refreshes.

1. Single Source of Truth (SSOT) – Foundation Layer
Problem

Multiplayer games were previously hardcoded in frontend constants.

Admin panel data and live platform behavior could diverge.

High risk for financial inconsistencies.

Solution

Introduced a dedicated multiplayer_games table in the database.

All game metadata is stored centrally:

game_key

display name (i18n-ready)

min/max stakes

platform fees

active / disabled status

No hardcoded game configuration remains in frontend or backend.

Business Impact

Zero configuration drift

Safe live operations

Faster iteration without redeployments

2. Real-Time Configuration Sync (WebSocket Driven)
Problem

Admin changes required client refresh.

Dangerous in live betting / challenges.

Solution

Added a system-level WebSocket event:

{
  "type": "system_event",
  "event": {
    "type": "game_config_changed"
  }
}

Frontend Behavior

Clients listen for system_event

On game_config_changed:

Invalidate cached queries

Re-fetch game configuration instantly

No refresh, no user action

Business Impact

Admin changes propagate instantly

Zero downtime updates

Live operations stay consistent
